### Gotcha worth remembering
A 200 from a Greenhouse slug is not proof of identity. The variant "shield" returns a
GitHub Pages demo board ("Copy of Avenger", Beijing) — not Shield AI. verify.py now
requires a guessed variant to prove itself via the /v1/boards/{slug} name (Greenhouse)
or the slug appearing in the posting URL path (Lever/Ashby). Seeded slugs are taken at
face value because many real boards apply through a custom domain, so the apply-URL
host proves nothing.

### Two bugs found and fixed by running it for real
- HN thread selection returned the March 2020 thread. Algolia's /search endpoint is
  relevance-ranked and returns 20 arbitrary hits, none recent, so "newest hit"
  was newest-of-an-old-sample. Now queries /search_by_date filtered to the
  whoishiring account, with /search kept as a fallback.
- On Windows stdout is cp1252, so the digest wrote an em dash as byte 0x97 and any
  character outside cp1252 would have raised UnicodeEncodeError *after* the whole
  run completed. main() now reconfigures stdout/stderr to UTF-8 with
  errors="replace".

## 2026-09-03 — us-remote + dedupe

20. --us-remote filter, on by default for run and list (--no-us-remote disables).
    Location must contain "remote" AND either name the US (United States/USA/US/
    North America/NA/AMER/Americas/state name or code) or name no country at all.
    Only the location is consulted - a description mentioning the US says nothing
    about where the role is based.
    Two ordering details matter: strong US tokens are checked BEFORE the foreign
    list so "Remote - NA, APAC, EMEA" survives; state codes are checked AFTER it
    so "CA-Ontario-Toronto" reads as Canada, not California. State codes match
    case-sensitively on the raw string so "in"/"or"/"ok"/"me"/"hi" are not read
    as Indiana/Oregon/Oklahoma/Maine/Hawaii.

### The delivery bug that took three sends to pin down
Gmail rewrites every URL in a message body into google.com/url?q=...&ust=1788...
The connector's quoted-printable encoder does not escape "=" as "=3D", so the
decoder reads the "=17" inside "ust=17..." as a QP escape for byte 0x17 and eats
it. Every unix-ms timestamp starts with 17, so this breaks EVERY link, forever.
It affects html href attributes too - an early test seemed to show HTML surviving,
but only because that test's markup was accidentally escaped, so Gmail
auto-linkified plain text and inserted its own anchor after encoding. Sending real
<a href> reproduced the corruption.
Fix: send the digest as a base64 ATTACHMENT with no URLs in the body. Verified:
attachment present, 31 hrefs, zero google.com/url wrappers, zero control bytes.
Python smtplib has neither problem (verified byte-identical round trip, 32/32
URLs intact) - relevant only if SMTP is ever configured.
